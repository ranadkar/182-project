# Four-way authorization experiment

Primary outcome is a first-turn net transition to the prespecified target on a discrepancy delivered under the external environment header. Fixed primary suite has 108 cases from 18 domains. The main comparisons are continuation minus explicit, factual minus explicit, and neutral minus explicit. Additional identification contrasts are factual minus neutral (specific factual reminder given a final user turn) and continuation minus neutral (omitting a non-directive user receipt). Rates and contrasts average three prespecified paired fitting seeds. Intervals resample entire domains and paired seed indices together. A second clustering analysis uses operation type. These are percentile intervals, with no multiplicity correction. Paired accuracy differences on explicit and ongoing tasks are diagnostics, never exclusion criteria.

Each case has a discrepancy and one matched control, with identical initial state, menu order and transition rules. Each domain has two ordinary, two ambiguous and two conflicting controls. Compare discrepancy and paired control within each control stratum, including a difference of these within-case differences across arms. For ordinary facts there is an affirmative current-state explanation. Ambiguity leaves key information missing. Conflict supplies incompatible current records. A unilateral change on either of the latter two is scored as a change under unresolved evidence. A read is a distinct action. The design never labels a target hit as correct outside authorized tasks.

Deliver each fact three ways, with fresh state and a forced assistant generation opportunity. Use the native user header, the earlier study's environment header, and a passive XML notification appended to the native system message with no user turn. Use identical fact bytes and the same native Qwen tool syntax and neutral system text. Use greedy decoding, 96 generated tokens, BF16 backbone, no thinking and first-turn-only execution. Log outputs and termination. Each case also has an explicit named write and a multi-step authorized reconciliation after a completed lookup. Repeat all five existing benchmark cells on the original 60 cases. The twelve old reserve templates are excluded.

The new collection has 132 authored cases, including two development domains (12 cases), 18 blinded evaluation domains (108 cases) and two unopened December holdback domains (12 cases). The 12 development workflows cover the twelve state-transition types. Check the simulator with reference and failure cases, and test all four pilot adapters on development controls. Separate model fit pilots use 32 training branches. The full fits use 256 branches, 32 updates and the same 4,909 masked target tokens per arm, with the inherited rank-16 BF16 LoRA configuration. Fitting and suite authorship can proceed concurrently. No model scores the new evaluation suite before the data, prompts, scoring code, comparison and analysis plan are frozen. Evaluate every final adapter with no model selection or interim tuning. The holdback never reaches an inference server in this study.

All four training contexts start with an authorized user goal, an assistant lookup and its result. On every decision, the explicit and factual arms share the exact reference-value sentence, even on a read (the specified reference is known but the current value is missing). The explicit arm adds an operation-specific request. The factual arm adds a receipt. The neutral arm retains that receipt after a sentence acknowledging possession of the paperwork without naming its field or value. Continuation appends no message. The read/write/no-action/text targets, schemas, histories, assistant tokens, sample order, matched maximum padding and step counts are fixed within seed. Target repetition thus includes grounding the field name, and the extra-turn manipulation includes acknowledgment language. Claims will be limited to these operational contrasts. Three paired seeds take priority over five because every additional seed requires another complete four-model behavioral panel on one laptop GPU.
