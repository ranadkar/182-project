# Qwen3.5-4B LoRA experiment design

**Estimand.** For the same starting checkpoint and the same supervised next-action tokens, measure the change in probability of an unsolicited, executable state change caused by training on task continuation with an implicit next step versus an explicitly requested next step. The strongest test is a fresh external observation with no user history. Evaluate the user-statement condition separately. Checkpoint comparisons between Olmo and Nemotron cannot identify this effect.

The observed baseline matters for endpoint selection. In the present study both checkpoints read frequently on ordinary events, all ordinary-state writes were idempotent, and only Nemotron changed state after a discrepancy notification (5/60). Olmo still completed 59/60 requested writes. This motivates keeping real state change, read-only behavior and task competence as separate measurements and retaining delivery role as a paired factor. ## Matched intervention

Use the text path of `Qwen/Qwen3.5-4B`, revision `851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`, with thinking off in all arms. Pin the tokenizer, Transformers and PEFT versions before generating token pairs. Initialize each pair of adapters identically from the frozen released checkpoint. Keep the unadapted checkpoint as a baseline. [Qwen release](https://huggingface.co/Qwen/Qwen3.5-4B/tree/851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a)

Construct 2,048 matched branches from simulated or manually audited task trajectories. Every branch starts with an explicit higher-level user goal and an authorized preliminary tool call. The observed result reveals the next step. Balance eight training domains and the distribution of tool names, argument types, target positions, state changes and read/write/stop decisions across arms by copying each trajectory. Use 768 write targets, 768 read targets and 512 ordinary closing responses or explicit no-op targets. Give stop examples the identical history and completion in both arms. Use independent trajectory families for adapter development. Record the origin, task authorization, pivot, action and termination reason for each branch.

| Arm | Context before the supervised next turn | Loss-bearing completion |
|---|---|---|
| A · Continuation | Shared user goal, first tool call and observed tool result | Recorded next call or stop |
| B · Explicit | Same prefix, plus a user request for that particular next operation on action examples | Byte-identical next call or stop |
| C · Role control | Same prefix, plus a factual user acknowledgement on action examples, matched to B in length | Byte-identical next call or stop |

For example, the goal is to prepare a loan packet for dispatch. A preliminary lookup returns the approved mailer size, M. In A the next assistant call selects mailer M. In B the customer adds “Select the medium mailer for this packet.” In C the customer adds “The packet label also lists a medium mailer.” All three targets select the same mailer using the same typed argument. The result already contained the size in all three arms. The A–B contrast includes the extra user turn by design. B–C helps identify sensitivity to explicit authorization with the user role and recency held fixed. Vary acknowledgment wording and audit it for covert requests.

**Token and compute matching.** Train only on the final assistant token span and its terminator. Mask all context, previous assistant messages, role headers and padding with label `-100`. Render with the same Qwen template, tokenize the full conversations and assert that every paired sequence of supervised token IDs is identical. Check counts by tool, action and target type. Keep only examples that fit in 2,048 tokens in every arm. Use identical pair IDs in each minibatch with identical target-token loss normalization. Pad paired examples to the same length or use matched fixed-length batches. Padding equalizes tensor shapes, while B still contains extra attended text. C addresses that residual format difference.

**Proposed budget.** Train a 4-bit NF4 frozen backbone with BF16 compute and rank-16 LoRA adapters on the text decoder MLP gate, up and down projections. Use alpha 32, dropout 0.05, gradient checkpointing, microbatch 1 and gradient accumulation 16. Inspect resolved module paths and trainable parameter counts before fitting. Keep the vision tower, embeddings and output head frozen. Use AdamW, learning rate 0.0001, five percent warmup and two epochs. At batch 16 the budget is 256 optimizer updates per arm. Pair five seeds across A and B, using the same seed list for C if resources permit. Time a short development run to verify memory and throughput. Fix final-step selection using a disjoint development protocol before scoring any held-out case.

## Evaluation and interpretation

1. Use this study's frozen 60 templates for comparability and the 12 reserved templates from ceramics and sports administration as a separate domain-transfer test. Exclude all 72 families, their tool names, observation wording and paraphrases from training and tuning. Group by underlying workflow before sampling any train/development split. Check exact and near-duplicate overlaps and review high-similarity pairs. Additional test families should be authored and frozen blind to adapter outputs.
2. Preserve the same factual inputs, typed transitions, balanced tool order and four role-by-state cells. Add an explicitly authorized multi-step branch on a disjoint competence set. Report read/write/no-action calibration, single-step requested-write success, authorized continuation success and parser errors for each adapter. Keep every test case in the denominator, including competence failures.
3. Qwen's published template checks for a user query and rejects unknown message roles. For the notification manipulation, render a normal user statement using the native tool schema and generation suffix, then replace only the final ChatML input-role header with `environment` before tokenizing. Assert that the resulting string contains **zero** user turns, identical observation bytes and the intended assistant suffix. Use this explicit protocol extension for every arm and baseline. Confirm the Qwen native call parser with positive controls. A separate evaluation can vary the event envelope to measure dependence on the novel role. [Pinned Qwen template](https://huggingface.co/Qwen/Qwen3.5-4B/blob/851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a/chat_template.jinja)
4. Preregister A minus B in actual first-turn change rate on discrepancy notifications as primary. Secondary endpoints include matched-direction changes, ordinary-notification changes, user-statement changes, reads, idempotent writes and recognized invalid attempts. Report the difference between discrepancy and ordinary as a paired interaction across training arms. Require evidence of preserved explicit-task competence before interpreting a rate change as transfer. Retain raw signed effects if this diagnostic fails.
5. Estimate uncertainty with paired, crossed resampling of training seeds and scenario families, keeping arm assignments and all cells together. Report individual seed contrasts. Compute a sensitivity analysis clustered by domain. Greedy reruns or multiple paraphrases of one situation contribute no additional independent scenario units. Sixty cases give a 1.67-point increment per success per adapter. For planning, a 10-point effect with a 0.20 discordant-pair probability needs roughly 157 independent pairs at 80% power and two-sided 5% under a normal approximation. A five-point effect at that discordance needs roughly 628. Those figures omit seed variability and domain correlation. Use the frozen suite for the initial comparison and budget additional independent families for a confirmatory study of a small effect.

Increased target-matched changes on fresh notifications, with stable requested-write competence, would support transfer under this intervention. An increase confined to explicit-task or open-task controls would indicate improved task execution. Increased calls accompanied primarily by repeated writes of the current value would suggest a tendency to record observations. Treat the 12-case reserve as a small transfer check and disclose any use of its results for later design choices.
